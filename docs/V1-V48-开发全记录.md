## 0. 起点与终点

| | |
|---|---|
| 设备 | 小米 6（`sagit`）· 骁龙 835 · 4 GB/6 GB · A-only · **4Kn 逻辑扇区** |
| 基线 | OrangeFox R12.1（`fox_12.1`，Android 12.1 代码基） |
| 内核 | 4.4（prebuilt，三个 `Image.gz-dtb`） |
| 起点 | 2026-11-20 08:12，源码 + 旧设备树，第一次编译 |
| 终点 | 2026-11-23 20:26，V48 正式发布版 |
| 节点 | 83 个（其中 v23 只停在规划，从未产出镜像） |

**为什么难**：小米 6 是 2017 年的机器，4.4 内核 + A-only 分区 + 4Kn 扇区，而 `fox_12.1` 面向的是 Android 12 时代的设备。两者之间的每一处不匹配，都要在 recovery 里补回来：没有 health HAL、没有动态分区、没有 A/B、fb 设备在 `/dev/graphics/fb0`、加密是 FBE(ice) 而不是 FDE。

## 2. 五个值得记住的 bug

### 2.1 OTG 其实一直是好的（v10 – v13）

现象：插 U 盘无反应。前四版都在猜 USB 角色切换：写 `mode=host`、写三个开关节点、查 gadget 绑定 —— 全错。

真因在 `PartitionManager` 里：**挂载失败后，卷的 `Mounted` 状态没有复位**，被永久记为「已挂载」。之后再插 U 盘，代码判断「已挂载」直接跳过。加上 `ntfs-3g` 缺失（v13），两个问题叠加成「OTG 坏了三年」。

> 修法：挂载失败时显式 `UnMount()` 或清 `Mounted` 标记，别让失败变成「成功」的残留状态。

### 2.2 ADB Sideload（v20 – v33）

不是 configfs 缺配置块，是 **USB 触发段里没有启动 adbd**。移植 OrangeFox 24.03.16 的 `start adbd` + gadget 重配之后，全流程可用。

### 2.3 格式化 Data 五连败（v36 – v40）

见 §1 ⑥。核心：**分支没走对，改多少实现都无效。**

`tw_wipe_data_use_rmrf` 在设置里默认可能为 1，`Wipe_Data()` 一进来就进「只删文件」分支，`mkfs` 那一整段根本不执行。

### 2.4 列表回弹（V46-8 → V46-11）

现象：分区单选列表（6 项）拉到底再上拉，会弹回原位。

- V46-8：以为惯性把列表带出边界 → 在 `TOUCH_RELEASE` 里钳 `scrollingSpeed`。**无效**，因为 `contentH > windowH` 这个前提不成立，补丁根本没触发。
- V46-9：拦 `TOUCH_DRAG` 源头 + 底部 `>=` 钳制。**无效**，同上。
- V46-10：`Render()` 每帧无条件钳制。**无效**，因为每帧算出来的「合法范围」本身就多于可视高度。
- V46-11：真因 —— **6 项 × 90px = 540px 正好一屏，但样式带 `<padding top="40" bottom="40"/>`，滚动逻辑把 padding 计入内容高度，凭空多出 80px「幽灵滚动」**。

> 修法：`ItemsFitWindow()` 判定「所有行装得下」时，强制 `firstDisplayedItem=0; y_offset=0; scrollingSpeed=0`，并且命中检测跳过 padding（`SkipGroupPadding()`）。即「行装得下就不许滚」。

**通用教训**：滚动问题的第一件事是打印 `contentH`、`windowH`、`mItemPaddingTop/Bottom`，看内容高度是怎么算出来的，而不是去调惯性参数。

### 2.5 扩容 12G「报失败」但已生效

脚本用 `warn()` 累计失败次数，任何一步失败就 `exit 3`。大跨度（5G → 12G）时分区表重写 + `mke2fs` + f2fs 重建叠加，是全程 I/O 峰值，收尾校验偶尔超时被判失败 —— **分区表其实已经写好，重启格式化后正常**。

另有一次「12G 刷完不开机」，实际是刷机后没格式化 Data：扩容后 Data 是全新分区，旧 f2fs 元数据对不上，卡第一屏一两秒自动重启。**正确顺序：扩容 → 重启 recovery → 格式化 Data → 刷包。**

## 3. 核心改动（代码级）

### 3.1 滚动：`ItemsFitWindow()` / `SkipGroupPadding()`

`bootable/recovery/gui/scrolllist.cpp`

```cpp
// 所有行（含组标题）总高 <= 可视高度时，列表不允许滚动
bool GUIScrollList::ItemsFitWindow() { ... }
// 组内 padding 不参与滚动范围计算
bool GUIScrollList::SkipGroupPadding() { ... }
```

`Render()` 与 `HandleScrolling()` 里，只要「装得下」，每帧都把 `firstDisplayedItem`、`y_offset`、`scrollingSpeed` 归零；`NotifyTouch()` 的命中检测同样跳过 padding。

`gui/listbox.cpp` 的 `SetPageFocus()` 里补了一层：没有 `<data>` 绑定的列表，刷新会把每一项（变量值都为空）判定为「选中」，从而把视图拉到最末项 —— 进入页面时强制回顶部。

> 编译注意：源码注释里**不能出现非 ASCII 字符**（em dash 会触发 `-Werror=comment`）。

### 3.2 扩容脚本：`fox_resize_system.sh`

`device/xiaomi/sagit/recovery/root/sbin/fox_resize_system.sh`

流程：

1. 卸载 `/system` `/cust` `/data` 及 `/storage` 下所有 bind mount（按设备路径逐点卸，5 轮，卸不掉 `exit 5`）
2. 从分区表读实际扇区（不靠猜），算出 `system` 目标终点
3. `sgdisk` **长参数**删除同名 `system` / `cust` / `userdata`（跨 LUN 也删），从 114688 扇区重排
4. 重建 `cust` 832 MiB，`data` 后移
5. 写完立即校验三块，缺一块 `load-backup` 回滚
6. `mke2fs`（带 `mke2fs.conf`）/ `make_f2fs`（`dev_sz` 用 512 作块大小），失败依次降级，结果写 `ACTUAL_FSTYPE`

**关键参数**：

| 项 | 值 | 说明 |
|---|---|---|
| 原厂 system | 5120 MB | 实测，不是截图上的 5117 |
| cust | 832 MiB | 实测，不是最早写的 656 |
| 扇区 | 4096 B | 4Kn，所有计算按扇区而非 512B |
| 起始扇区 | 114688 | system 原起点 |

### 3.3 格式化分支：两条路必须分开

- **「更改文件系统」**：强制 `mkfs`，忽略 `tw_wipe_data_use_rmrf`
- **「格式化 Data」**：尊重 `tw_wipe_data_use_rmrf`，用户选择 rm -rf 就只删文件

`partition.cpp` 里新增 `Force_FS_Rebuild` 标志区分两者；`Wipe_F2FS()` 补上按设备强制卸载（原来只有一个 `UnMount()` 调用，卷被占用时直接 `rc=-1`）。

f2fs 兼容开关：`OF_F2FS_LEGACY_FEATURES=1` 时只启用 `encrypt+extra_attr`，否则 Android 默认 profile 会带上 quota/verity，4.4 内核挂不上。

### 3.4 重启到 Recovery：BCB + 清标记

`twrp-functions.cpp` 写 `bootloader_message`（`command="boot-recovery"`，`recovery` 为空），然后正常 `reboot()`；`recovery_main.cpp` 启动时读 `/misc`，发现是「裸 boot-recovery」就立刻清空，防止下一次重启又进 recovery。

`/misc` 解析：TWRP 的 fstab 不是 `fs_mgr` 格式，`get_bootloader_message_blk_device()` 拿不到时回落到 `/dev/block/bootdevice/by-name/misc`。

### 3.5 zip 脚本 reboot 不生效

三件套：

1. 静态链接的 `foxb_reboot`（`device/xiaomi/sagit/foxb_reboot.c`）直接调内核 `reboot(2)`，不依赖 toybox
2. `/sbin/reboot` 包装脚本，优先 `foxb_reboot`，失败回落 `toybox reboot`
3. `sepolicy/twrp.te` 加 `allow recovery self:capability sys_boot;`

### 3.6 手电筒轻点切换

`gui/gui.cpp` 的 `process_EV_KEY()`：音量上 / 电源任一按下时，若另一键在 400ms 内按下，判定为组合键，立即切换手电筒，并设 `g_suppress_power_toggle_until_ms` 防止松手熄屏。原生实现要长按 200ms，轻点无反应。

### 3.7 主题生效：rsync 强制同步

`bootable/recovery/Android.mk` 里主题拷贝早于 ramdisk 打包。加 rsync 强制同步后，改 XML 才会真正进镜像。

> 判断「改动进没进镜像」：解包 `ramdisk.img`，看 `twres/` 下文件内容，而不是看源码树里的文件。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 三大金刚键不响应 | TWRP 12.1 的 minui 丢弃 `EV_KEY`，上游行为 |
| 扩容有约 3.7% 容量损耗 | 4Kn 对齐 + 文件系统元数据，固定开销，不可消除只能稳定 |
| 大跨度扩容偶发 `exit 3` | 分区表已写入，重启后格式化 Data 即正常；属误报 |
| 扩容会清空 Data | 脚本与界面均有红字警告，必须先备份 |
| 5G 缩回比原厂少约 80 MB | 分区起止对齐位置变化，一次性差异 |

## 6. 如果重来一次，会先做这些

1. **先打通「改动如何进镜像」**。v7 之前所有 UI 改动都是无效功，因为改的文件根本没进 ramdisk。
2. **先写镜像解包脚本**。不要靠「刷进去看看」验证，解包 `ramdisk.img` 看 `twres/` 内容，30 秒出结果。
3. **先确认分支**。格式化 Data 五连败、OTG 四版空转，都是因为改的代码没被执行。
4. **坐标只用实测值**。字号 ≠ 行高，36px 字实际占 45px；居中文字宽度按「中心点 × 2」算会出错。
5. **滚动问题先打印高度**。`contentH`、`windowH`、padding，三个数字一比就知道问题在哪。
6. **失败如实标注**。图上 v23 写「未产出」、V46-8/9/10 写「未成」，不把失败包装成成功 —— 后面排查才有参照。
7. **每版留镜像 + MD5**。83 个节点里，能回退才有资格试错。
