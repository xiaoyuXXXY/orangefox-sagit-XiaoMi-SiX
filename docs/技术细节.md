## 1. `0001-scroll-list.patch` —— 列表滚动

### 问题

分区列表 6 项、每项 90px，正好一屏（540px），却还能上下拖动并回弹。原因是样式里的 `<padding top="40" bottom="40"/>` 被滚动逻辑算进了内容高度，凭空多出 80px「可滚动区域」。

### 改动

`gui/objects.hpp`

```cpp
bool ItemsFitWindow();     // 所有行（含组标题）总高 <= 可视高度
bool SkipGroupPadding();   // 组内 padding 不计入滚动范围
```

`gui/scrolllist.cpp`

- `Render()`：装得下时，每帧强制 `firstDisplayedItem = 0; y_offset = 0; scrollingSpeed = 0;`
- `HandleScrolling()`：同上，滚动入口直接返回
- `NotifyTouch()` / 命中检测：`SkipGroupPadding()` 为真时跳过顶部/底部 padding，避免点击落点偏移
- 相关函数：`GetDisplayRemainder()`、`GetItemHeight()`、`GetGroupItemHeight()`

`gui/listbox.cpp`

- `NotifyVarChange()`：`mVariable` 为空时不再把每一项判为「选中」（原来空值 == 空值，全部命中）
- `SetPageFocus()`：进入页面强制回顶部

`gui/fileselector.cpp`

- `SetPageFocus()`：同样回顶部（打开文件默认不再停在最底）

> 编译注意：这些文件里的注释必须是纯 ASCII。em dash（—）会触发 `-Werror=comment`。

## 2. `0002-partition-expand.patch` —— 分区与格式化

### `partition.cpp`

| 位置 | 改动 | 为什么 |
|---|---|---|
| 头部 | 加 `#include <sys/mount.h>` | `umount2()` |
| 约 779 行 | 新增 `Fox_Force_Unmount_Device(path)`：按设备路径循环 `umount2(MNT_DETACH)` 最多 5 轮 | 卷被 bind mount 占用时，`UnMount()` 静默失败，后续 `mkfs` 报 `rc=-1` |
| 约 1345 行 | `Wipe_Data()` 入口识别 `Force_FS_Rebuild`，忽略 `tw_wipe_data_use_rmrf` | 五连败的真因：rm -rf 开关优先级最高，`mkfs` 分支根本不执行 |
| 约 1901 行 | `Wipe_EXTFS()` 前先强制卸载 | 同上 |
| 约 1913 行 | `Wipe_F2FS()` 前先强制卸载 | 「更改文件系统 → F2FS」`rc=-1` |
| 约 2273 行 | FBE 分支补 `Recreate_Media_Folder()` | 格式化后 `/data/media` 没重建，相机/存储异常 |
| 约 2326 行 | FBE 分支补 `Mount()` | 整条分支原来不挂载，界面显示完成但实际未挂上 |
| 约 2427 行 | `Remove_Legacy_Media_Symlink()` + `/data/Media` 清理 | v21 留下的软链会误导后续判断 |
| 约 2506 行 | `Disable_MTP()` / `Add_MTP_Storage()` 时机调整 | 插 U 盘不再永久关闭 MTP |
| 约 2735–2863 行 | f2fs 特性按 `OF_F2FS_LEGACY_FEATURES` 收窄；`dev_sz` 块大小 4096 → 512 | 4.4 内核不认 quota/verity；块大小算错会把 112 GB 格成 14 GB |
| 约 3584 行 | 分区大小探测改为读分区表 | 不再按截图猜（5120 MB / 832 MiB 是实测值） |

### `partitionmanager.cpp`

- 挂载失败时复位卷状态（OTG 三版空转的真因：失败被永久记为「已挂载」）
- 分区管理扁平化：第一层直接进分区列表
- 扩容入口：`fox_resize_system.sh` 的调用与返回码处理

### `partitions.hpp`

- `Partition` 增加 `Force_FS_Rebuild` / 实际文件系统类型字段

## 3. `0003-recovery-core.patch` —— 行为修正

### 默认时区（`data.cpp` + `orangefox.mk`）

```cpp
mPersist.SetValue(TW_TIME_ZONE_GUIDST, "0");   // 原为 "1"
```

```make
LOCAL_CFLAGS += -DOF_DEFAULT_TIMEZONE='"CST-8"'   # 原为 CET-1;CEST,M3.5.0,M10.5.0
```

中国时区没有夏令时，`GUIDST=1` 会让时间偏一小时。

### 手电筒轻点（`gui/gui.cpp`）

`InputHandler::process_EV_KEY()`：音量上 / 电源任一按下，若另一键在 400ms 内按下，立即 `flashlightImpl("")`，并设 `g_suppress_power_toggle_until_ms = now + 800` 防止松手熄屏；`key_status = KS_KEY_REPEAT` 阻止长按逻辑重复触发。

### 重启到 Recovery（`recovery_main.cpp` + `twrp-functions.cpp`）

写入：

```cpp
bootloader_message boot = {};
strcpy(boot.command, "boot-recovery");   // recovery 字段留空
write_bootloader_message_to(boot, misc_dev, &err);
```

启动清理（`recovery_main.cpp` 开头）：读 `/misc`，若 `command == "boot-recovery"` 且 `recovery[0] == '\0'`，立即写空消息清掉 —— 否则下次重启又进 recovery。

`/misc` 解析：TWRP 的 fstab 不是 `fs_mgr` 格式，`get_bootloader_message_blk_device()` 取不到时回落 `/dev/block/bootdevice/by-name/misc`。

### zip 脚本 reboot（`twrp.cpp` + `twrp-functions.cpp`）

- `tw_reboot()` 的 `rb_recovery` 分支改走上面的 BCB 流程
- 静态 `foxb_reboot`（`device/xiaomi/sagit/foxb_reboot.c`）直接调 `reboot(2)`
- `/sbin/reboot` 包装脚本：优先 `foxb_reboot`，失败回落 `toybox reboot`
- `sepolicy/twrp.te`：`allow recovery self:capability sys_boot;`

### f2fs 兼容开关（`orangefox.mk`）

```make
ifeq ($(OF_F2FS_LEGACY_FEATURES),1)
    LOCAL_CFLAGS += -DOF_F2FS_LEGACY_FEATURES
endif
```

配合 `partition.cpp`，Android 默认 profile 只保留 `encrypt+extra_attr`。

## 4. `0004-theme-ui.patch` —— 界面

### 页面结构

```
twres/pages/advanced.xml    晓宇插件主页（三段分组 + 内核组 + 顶部红字 + 底部四行）
twres/pages/fox.xml         扩容流程（选容量 → 确认 → 执行 → 完成页）
twres/pages/settings.xml    精简（合并条目，去掉重复项）
twres/pages/*.xml           若干文案与返回目标修正
```

### 关键坐标（`advanced.xml`）

| 元素 | 值 |
|---|---|
| 组标题 / 卡片 | 276/326、618/668、960/1010、1302/1352 |
| 组标题字号 | 36px 橙 |
| 标题→卡片间距 | 55px（35px 会切字，实际行高约 45） |
| 卡片高度 | 288px（2 × 144；低于 288 出组内滚动条） |
| 红字两行 | x=268 y=190 / x=227 y=228，中心同在 x=540 |
| 底部四行 | `cjk_xs` 31px，y=1650/1683/1716/1749 |

### 字体（`resources/images.xml`）

```xml
<font name="cjk_xs" filename="wqy-microhei.ttf" size="31"/>
```

### 其它

- `vars.xml`：`fastscroll_w=0`、`fastscroll_rectw=0`（去掉右侧黄条）
- `splash.xml` / `images/Splash/user.png`：启动图
- `images/Default/About/*`：关于页（整屏插画 + 维护者）

> 所有坐标写死数字。`LoadAttrInt()` 不做四则运算，`y="100+50"` 会被 `atoi` 截成 100。

## 6. 设备树侧（不在补丁里）

`device/xiaomi/sagit/`

| 文件 | 作用 |
|---|---|
| `BoardConfig.mk` | 分区尺寸、kernel cmdline、4Kn 扇区、`OF_*` 开关 |
| `twrp_sagit.mk` | 产品配置，`ro.hardware.keystore=msm8998` 等 |
| `recovery.fstab` | 分区表；`/splash` 已删（小米 6 的 boot 与 logo 分开，留着会显示重复 Boot Logo） |
| `recovery/root/sbin/fox_resize_system.sh` | 扩容脚本（见下） |
| `recovery/root/sbin/fox_sysinfo.sh` | 分区/文件系统信息，扩容页显示当前容量 |
| `recovery/root/sbin/reboot` | reboot 包装 |
| `foxb_reboot.c` | 静态 reboot helper |
| `recovery/root/vendor/lib64/*` | keymaster / gatekeeper 依赖 |
| `prebuilt/Image*.gz-dtb` | 三个 4.4 内核 |

### 扩容脚本流程

```
卸载 /system /cust /data + /storage 下 bind mount（5 轮，失败 exit 5）
  ↓
读分区表实际扇区（不猜）
  ↓
sgdisk 长参数删除同名 system/cust/userdata（跨 LUN）
  ↓
从 114688 扇区重排：system 目标大小 → cust 832 MiB → data 后移
  ↓
写完立即校验三块，缺一块 load-backup 回滚
  ↓
mke2fs / make_f2fs（失败降级），结果写 ACTUAL_FSTYPE
```

参数常量：原厂 system = **5120 MB**，cust = **832 MiB**，扇区 4096 B，system 起始 **114688**。

## 7. 改动自检清单

改完任何一处，按这个顺序确认，能省掉大部分「改了没用」：

1. `bash build/clean-rebuild.sh`（强制重打 ramdisk）
2. `bash build/build.sh`
3. `python3 scripts/verify_img.py check <img>`
4. 关键内容抽查：`verify_img.py cat <img> twres/pages/advanced.xml | grep 晓宇`
5. 刷机，看 `recovery.log`（`/tmp/recovery.log` 或 `/sdcard/Fox/recovery.log`）
