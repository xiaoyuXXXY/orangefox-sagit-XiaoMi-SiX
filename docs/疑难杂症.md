# 疑难杂症 · 按症状查

三条经验先放前面：

1. **报错文案经常在骗人。** 译文是错的，变量名和代码才是真的。
2. **「改了没用」先确认改动进没进镜像**，而不是继续改代码。
3. **失败要留下现场**：`/tmp/recovery.log`、`/sdcard/fox_resize_error.txt`。

---

## 一、界面 / 主题

| 症状 | 真因 | 处理 |
|---|---|---|
| 改了 XML 或图片，刷进去完全没变 | ramdisk 打包早于主题写入，改动没进 `ramdisk.img` | `build/clean-rebuild.sh` 后重编；用 `verify_img.py cat` 确认镜像里的真实内容 |
| 坐标写 `y="100+50"` 位置不对 | `LoadAttrInt()` 不认算式，`atoi("100+50")` = 100 | 全部写静态数字 |
| 卡片压住橙色组标题 / 字被切一半 | 字高 ≠ 字号。36px 字实际行高约 45，间距给 35 就切 | 标题与卡片间距 55px |
| 列表最后一项显示不全 | 列表高度是编译期常量（512），项数超了就裁 | 改 XML 里的高度，或改用可滚动列表 |
| 分区列表拉到底再上拉会回弹 | `padding top=40 bottom=40` 被算进内容高度，6×90px 正好一屏却多出 80px 可滚区 | 「行装得下就不许滚」：`ItemsFitWindow()` + `SkipGroupPadding()`（补丁 0001） |
| 一进附加页 / 文件页就停在最底 | 没有 `<data>` 绑定的列表，变量值为空，刷新时每项都被判为「选中」 | `SetPageFocus()` 强制回顶部（`listbox.cpp` / `fileselector.cpp`） |
| 右侧一条黄色滚动条，没用还挡视线 | 快滚条默认开启 | `vars.xml`：`fastscroll_w=0`、`fastscroll_rectw=0` |
| 分组卡片里出现滚动条 | 卡片高度小于「项数 × 144」 | 卡片高度固定 288px（2 项） |
| 三大金刚键没反应 | TWRP 12.1 的 minui 丢弃 `EV_KEY` | 上游行为，非本包缺陷，用触摸或音量键 |
| 手电筒轻点没反应 | 原生实现要长按 200ms | `gui.cpp` 检测「音量上 + 电源」400ms 内组合，立即切换 |
| 编译报 `-Werror=comment` | 源码注释里有中文标点 / em dash | 注释只写 ASCII |
| 启动页背景被黑色盖住 | `<fill color="black">` 铺满整屏，盖住了后面的 `<image>` | fill 放 image 之前，或缩小 fill 区域 |

## 二、硬件 / 功能

| 症状 | 真因 | 处理 |
|---|---|---|
| 电量一直显示空 | 4.4 内核没有 health HAL | 直读 `/sys/class/power_supply/battery` |
| 插 U 盘（OTG）没反应 | 挂载失败被永久记为「已挂载」，后续直接跳过 | 失败时复位卷状态；补 `ntfs-3g` |
| 写 `mode=host` 也没用 | gadget 绑着 UDC 时写 mode 是空操作 | 不要在这条路上继续试 |
| ADB Sideload 卡在 starting | USB 触发段没有启动 adbd | 移植 24.03.16 的 `start adbd` + gadget 重配 |
| 提示「找不到 Media 存储」 | `mtp_enabled` 被错译，跟存储无关 | 修 MTP 启动逻辑，别去修挂载 |
| 插过 U 盘后 MTP 永久失效 | 挂 U 盘时把 MTP 关了，拔了没恢复 | 拔盘后重新 `Add_MTP_Storage` |
| 输入密码后解密卡住 | 缺 qseecomd / keymaster / gatekeeper，或 fstab 写成 FDE | `fileencryption=ice` + 三个 HIDL 服务齐全 |
| 格式化 Data 后变英文 | 默认语言只在首次写 | 三道保险：编译默认值 / 无选择时反向强制 / 语言页记录 |
| 重启到 Recovery 后无限进 recovery | BCB 里的 `boot-recovery` 没清 | `recovery_main.cpp` 启动时清掉裸 BCB |
| zip 刷机脚本里 `reboot` 不重启 | toybox reboot 在 recovery 权限不足 | 静态 `foxb_reboot` + `/sbin/reboot` 包装 + sepolicy `sys_boot` |
| 刷分区界面出现两个 Boot Logo | fstab 里有 `/splash`，小米 6 的 boot 与 logo 是分开的 | 删掉 fstab 的 splash 条目 |

## 三、扩容 / 分区（重点）

| 症状 | 真因 | 处理 |
|---|---|---|
| 点扩容没反应，提示「进程错误 1」 | 脚本没有执行位，或 `/sbin/sh` 不是 bash | `chmod 755 fox_resize_system.sh`；脚本已内置解释器回退 |
| 扩容显示失败（`exit 3`），但重启后 system 确实变大了 | 收尾校验在 I/O 峰值时超时，`warn()` 累计后 `exit 3` | 属误报。重启 Recovery → 格式化 Data → 刷 ROM |
| 扩容后刷完 ROM 不开机，卡第一屏一两秒重启 | data 是新分区，旧 f2fs 元数据对不上 | 必须先格式化 Data 再刷 ROM |
| 格式化 Data 界面显示完成，实际挂不上 | `mke2fs` 写出 64bit / metadata_csum，4.4 内核不认 | 补 `mke2fs.conf`，限制特性 |
| 格式化 Data 后相机 / 文件管理器报存储不可用 | `/data/media` 没重建 | `Recreate_Media_Folder()` + chown/chmod/restorecon |
| 「更改文件系统 → F2FS」报 `rc=-1` | `Wipe_F2FS()` 只有一个敷衍的 `UnMount()`，卷被占用 | 按设备路径强制卸载，5 轮 |
| data 被格成 14 GB（本该 112 GB） | make_f2fs 的 size 参数块大小用了 4096 | 用 512，或干脆不传 size 让它自己算 |
| 分区表里出现好几组 system / cust | 历次失败残留 | 按名字删光全部，不只看「表里那一个」 |
| ROM 刷进了新 system，系统却从旧的启动 | 两块 LUN 上都有 system，by-name 指向旧的 | 扫描其它 `sd?` 删同名分区（脚本第 2.5 步） |
| 扩容后 data 只剩 3 GB 就报空间不足 | cust 用了写死的 656 MiB，或者 system 起点算错 | cust 下限 832 MiB；起点取 cache 结束扇区 +1 |
| 加密开关重启就失效 | 持久化写完又被 `Setup_Verity_Forced_Encryption()` 无条件清零 | 改清零逻辑，尊重用户选择 |
| 安装 Magisk 后卡开机 | 系统分区被改过但没重新签名 / verity 未处理 | 用包内 Magisk 流程，先装再改 |

## 四、编译

| 症状 | 原因 | 处理 |
|---|---|---|
| `ninja: unknown target 'recoveryimage'` | `lunch` 失败 / 设备树不在 `device/xiaomi/sagit` | 检查路径，重跑 `lunch twrp_sagit-eng` |
| `soong` 被 Killed | 内存不足 | `-j2`，或加 swap |
| 编译过了，刷进去界面没变 | ramdisk 没重打 | `clean-rebuild.sh` |
| `ninja_wrapper Error 1`，无具体错误 | `out/` 缓存损坏 | 删 `out/target/product/sagit` 重编 |
| 首次编译 40 多分钟正常吗 | 全量就是这么久（-j6，8 核） | 增量 3 分钟 |

## 五、定位问题的最小工具集

```bash
# 镜像里到底有什么
python3 scripts/verify_img.py ls   <img> twres/pages
python3 scripts/verify_img.py cat  <img> twres/pages/advanced.xml

# 扩容计划（不动分区，只看会怎么排）
/sbin/fox_resize_system.sh plan 8

# 现场日志
/tmp/recovery.log
/sdcard/fox_resize_error.txt
/sdcard/fox_resize_done.txt
```

真机上排查的顺序建议：**先看日志确认走到哪一步 → 再看代码那条分支会不会被执行 → 最后才改实现。**
