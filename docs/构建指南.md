# 构建指南

从零把 `OrangeFox-sagit-V48.img` 编出来，在一台干净的 Ubuntu 上大约需要 **2–4 小时同步 + 45 分钟全量编译**。

---

## 1. 环境

| 项 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04 LTS（20.04 也可，JDK 版本要对） |
| CPU | 4 核起，8 核更好（`-j` 按核数给，6 核给 `-j6`） |
| 内存 | **16 GB 起**。8 GB 必须 `-j2`，否则 soong 会被 OOM 杀掉 |
| 磁盘 | 源码 80–100 GB + `out/` 40 GB，**预留 200 GB** 比较稳 |
| JDK | **OpenJDK 11**（Android 12.1 只认 11，17 会报错） |

### 安装依赖

```bash
sudo apt update
sudo apt install -y openjdk-11-jdk git gnupg flex bison build-essential zip curl \
    zlib1g-dev gcc-multilib g++-multilib libc6-dev-i386 lib32ncurses5-dev \
    x11proto-core-dev libx11-dev lib32z1-dev libgl1-mesa-dev libxml2-utils \
    xsltproc unzip fontconfig python3 python3-pip imagemagick ccache schedtool

# 22.04 上 ncurses 单独装（名字变过）
sudo apt install -y libncurses5 libncurses5-dev 2>/dev/null || true

# repo
mkdir -p ~/bin
curl https://storage.googleapis.com/git-repo-downloads/repo > ~/bin/repo
chmod a+x ~/bin/repo
export PATH="$HOME/bin:$PATH"     # 写进 ~/.bashrc
```

> 构建过程需要联网（repo sync 约 76 GB）。

## 2. 同步源码

用 OrangeFox 官方同步工具，不要自己 `repo init` 拼 manifest。

```bash
mkdir -p ~/OrangeFox_sync && cd ~/OrangeFox_sync
git clone https://gitlab.com/OrangeFox/sync.git
cd sync
./orangefox_sync.sh --branch 12.1 --path ~/fox_12.1
```

- `--path` 必须是**绝对路径**
- 中途失败不要 `--force-sync` 硬来，先看报错（常见是网络断、磁盘满）
- 同步完 `~/fox_12.1` 应该在 **70–80 GB**

## 3. 放设备树

```bash
mkdir -p ~/fox_12.1/device/xiaomi
cp -a /path/to/this-repo/device/xiaomi/sagit ~/fox_12.1/device/xiaomi/
```

检查三件事：

```bash
ls ~/fox_12.1/device/xiaomi/sagit/BoardConfig.mk          # 存在
ls ~/fox_12.1/device/xiaomi/sagit/prebuilt/Image.gz-dtb   # 15 MB 左右
ls -l ~/fox_12.1/device/xiaomi/sagit/recovery/root/sbin/fox_resize_system.sh   # 要有执行位
```

> `fox_resize_system.sh` 必须可执行。丢失执行位的话，recovery 里点扩容会直接「进程错误 1」——这是 V44-8 踩过的坑。没有就用 `chmod 755` 补。

---

## 4. 打补丁

```bash
cd ~/fox_12.1/bootable/recovery
bash /path/to/this-repo/scripts/apply_patches.sh
# 或指定目录：REC_DIR=/path/to/recovery bash scripts/apply_patches.sh
```

逐个确认输出是 `[APPLY]`。如果某个补丁 `[FAIL]`：

| 情况 | 处理 |
|---|---|
| 提示 `patch does not apply` | 上游 `bootable/recovery` 已更新，`git log` 看改动，手工 `git apply --3way` 或按 patch 内容改 |
| 提示 `already applied` | 之前打过，跳过即可 |

补丁对应的上游基线：`bootable/recovery` commit `8cd9df2b4`（`fox_12.1`，2026-11）。

## 5. 编译

```bash
FOX_DIR=~/fox_12.1 bash /path/to/this-repo/build/build.sh
```

等价于：

```bash
cd ~/fox_12.1
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
export PATH="$JAVA_HOME/bin:$PATH"
export ALLOW_MISSING_DEPENDENCIES=true
export FOX_BUILD_DEVICE=sagit
source build/envsetup.sh
lunch twrp_sagit-eng
mka recoveryimage -j6
```

| 场景 | 耗时 |
|---|---|
| 首次全量（-j6，8 核机器） | 约 44 分钟 |
| 只改主题 / 设备树脚本（增量） | 约 3 分钟 |
| 改了 `bootable/recovery` 的 C++ | 约 5–10 分钟 |

产物：

```
out/target/product/sagit/OrangeFox-R12.0-Unofficial-sagit.img
```

### 强制重新打包 ramdisk

主题 XML、`recovery/root/sbin` 里的脚本、`recovery.fstab` 改了之后，增量编译**不一定**会重打 ramdisk。稳妥做法：

```bash
FOX_DIR=~/fox_12.1 bash /path/to/this-repo/build/clean-rebuild.sh
FOX_DIR=~/fox_12.1 bash /path/to/this-repo/build/build.sh
```

`clean-rebuild.sh` 只删 sagit 的产物，不动整个 `out/`。

## 6. 校验镜像（不用刷机）

```bash
python3 scripts/verify_img.py info  out/target/product/sagit/OrangeFox-R12.0-Unofficial-sagit.img
python3 scripts/verify_img.py check out/target/product/sagit/OrangeFox-R12.0-Unofficial-sagit.img
```

`check` 会确认：

- `twres/pages/advanced.xml`、`fox.xml`、`images.xml`、`vars.xml`、`zh_CN.xml` 在镜像里
- `sbin/fox_resize_system.sh`、`fox_sysinfo.sh` 在镜像里
- `advanced.xml` 含「晓宇插件」「NoksuEXT4.zip」「NoksuEROFS.zip」
- `fox.xml` 含「重启 Recovery」
- 扩容脚本含 `ACTUAL_FSTYPE`、`832`

全 `[OK]` 才算编对。**「源码改对了」和「镜像里是新代码」是两件事** —— 这是 v7 的教训。

其它用法：

```bash
python3 scripts/verify_img.py ls  <img> twres/pages      # 列目录
python3 scripts/verify_img.py cat <img> twres/pages/fox.xml   # 看镜像里的真实内容
```

## 7. 刷机

### 方式一：fastboot（推荐首次）

```bash
adb reboot bootloader
fastboot flash recovery OrangeFox-R12.0-Unofficial-sagit.img
fastboot reboot recovery
```

小米 6 需要先解 BL 锁，且 `fastboot flash recovery` 后**不要**用 `fastboot boot` 试（会覆盖）。

### 方式二：卡刷包

V32 之后有完整卡刷包（含 `recovery.img` + AromaFM / Magisk / uninstall / `fox.bashrc` / `INSTALL.txt`，官方签名）。在已有 recovery 里直接刷 zip。

### 扩容后的正确顺序（很重要）

```
扩容 → 重启 Recovery → 格式化 Data → 刷 ROM
```

扩容后 Data 是全新分区，旧 f2fs 元数据对不上，不格式化会卡第一屏一两秒然后自动重启。这不是「刷坏了」。

## 8. 常见错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `error: expected ';' before ...` 出现在注释行 | 源码注释里有非 ASCII 字符（em dash、中文标点） | 注释改纯 ASCII，`-Werror=comment` |
| `ninja: error: unknown target 'recoveryimage'` | 没 `lunch` 成功 / 设备树没放对 | 检查 `device/xiaomi/sagit` 路径，重跑 `lunch twrp_sagit-eng` |
| `soong` 被杀 / `Killed` | 内存不足 | `-j2`，或加 swap |
| 编译过了，刷进去界面没变 | ramdisk 没重打 | `clean-rebuild.sh` 后重编 |
| `make: *** [ninja_wrapper] Error 1` 且无具体错误 | out 缓存损坏 | `rm -rf out/target/product/sagit` 重来 |
| 扩容点了没反应 / 「进程错误 1」 | 脚本缺执行位，或 `/sbin/sh` 不是 bash | `chmod 755`；脚本已内置 toybox 回退 |
| 格式化 Data 显示完成但挂不上 | `mke2fs` 写出 4.4 内核不认的特性 | 确认 `mke2fs.conf` 已打进 ramdisk，`OF_F2FS_LEGACY_FEATURES=1` |
| 重启到 Recovery 后又进系统 | BCB 没写成功 | 看 `recovery.log` 里 `tw_reboot` 分支，确认 `/misc` 可写 |
